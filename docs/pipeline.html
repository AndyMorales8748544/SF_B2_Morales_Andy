GitHub Actions - Pipeline CI

El proyecto utiliza GitHub Actions para automatizar la verificación del código y la ejecución de pruebas.

1. Configuración del workflow

El archivo de configuración se encuentra en: 

.github/workflows/ci.yml

El workflow utiliza Ubuntu como entorno de ejecución y Node.js 24 para verificar la aplicación.

2. Eventos que activan el pipeline

  • Push a la rama feature/xyz.
  • Pull Request hacia develop.
  • Pull Request hacia main.

3. Etapas del pipeline

  1. Descargar el código mediante actions/checkout@v4.
  2. Configurar Node.js mediante actions/setup-node@v4.
  3. Verificar la sintaxis del archivo JavaScript.
  4. Ejecutar las dos pruebas automatizadas.
  5. Generar y publicar el archivo de resultados como artefacto.

4. Comandos de verificación

node --check script.js
node --test tests/registro.test.js

Resultado esperado: sintaxis válida, dos pruebas aprobadas y ninguna prueba fallida.

5. Casos de prueba

  • Registro válido: comprueba que el sistema acepta un nombre ingresado correctamente.
  • Registro inválido: comprueba que el sistema rechaza un nombre vacío.

6. Fallo controlado y solución

Se modificó intencionalmente una aserción para esperar false cuando el registro válido devolvía true. Esto provocó un AssertionError y una ejecución fallida.

Después se corrigió la aserción para esperar true. Las dos pruebas volvieron a aprobarse y el pipeline finalizó correctamente.

8. Resultados y publicación

El workflow genera el archivo resultados-pruebas.txt y lo publica como artefacto mediante actions/upload-artifact@v4.

La publicación de la documentación se realizará mediante GitHub Pages. Este workflow CI verifica el código y las pruebas; no despliega por sí mismo la aplicación a un servidor de producción.
