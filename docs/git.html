Estrategia Git y GitHub

El proyecto SF - Registro de Usuarios utiliza Git para controlar los cambios del código fuente y GitHub para gestionar el repositorio, las ramas y los Pull Requests.

1. Repositorio del proyecto

Ver repositorio en GitHub

2. Estrategia de ramas

  • main: contiene la versión estable.
  • develop: integra los cambios antes de publicarlos.
  • feature/xyz: permite desarrollar y probar funcionalidades.

El flujo utilizado fue feature/xyz hacia develop y, posteriormente, develop hacia main.

3. Comandos Git utilizados

git checkout main
git checkout -b develop
git checkout -b feature/xyz
git add .
git commit -m "Descripcion del cambio"
git push origin feature/xyz

Estos comandos ilustran la creación de ramas, el registro de cambios y su publicación en el repositorio remoto. Para crear feature/xyz desde develop, primero se debe cambiar a la rama develop.

6. Versionado del proyecto

Se creó la etiqueta v1.0.0 para identificar una versión estable de la aplicación. 

git tag -a v1.0.0 -m "Version 1.0.0 estable del sistema de registro de usuarios"
git push origin v1.0.0
